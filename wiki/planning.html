把建議變成能檢查的方案

先把要改的事寫成固定欄位，還不能直接當成通過

先填表，再決定能不能用

JSON 可以想成固定欄位的表單，像是要加入哪門課、移除哪門課，程式比較容易讀，也能擋掉格式錯誤，但表單填得漂亮，不代表課程真的排得進去。

產品和官方文件要分開看

Google 官方文件介紹用結構約束輸出，Campusward 這個版本的呼叫設定使用 JSON 回應類型，另外在本機解析欄位，不能直接說它已套用官方文件裡所有的 JSON Schema 功能。

這一頁的依據

  • C3 搜課由本機程式比對課程資料，AI 產生變更方案，不直接修改課表
    S3 小山的搜課與排課方案產生（orb.ts）
    定位：aiSearch、planWithAi；檔頭註解
  • C5 AI 套用會另外處理鎖定課與未知課程，並拒絕這次變更新造成或變嚴重的規則問題
    S9 AI 動作解析與套用前檢查（changeSet.ts）
    定位：applyAiChangeSet
  • C9 JSON 像固定欄位的表單，格式對不代表內容正確，Campusward 仍需本機解析與規則檢查
    S6 Gemini 連線、金鑰與錯誤處理（gemini.ts）、S5 依課綱回答與引用過濾（answer.ts）、S8 Google Gemini：Structured outputs
    定位：generate 的 responseMimeType、parseQaReply、官方 structured output 限制

來源編號能追到原文，這不是自動證明每句內容都正確，摘要仍需閱讀核對。
